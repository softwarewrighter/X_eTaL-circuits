# X_eTaL-circuits -- Design

The rules the code follows and the decisions behind them. A decision
is made with the user, recorded here with its reason, and changed
only by a later decision that says what it replaces.

## Rules

1. A capture is a directory: one XTLARR01 file per array, plus
   `capture.toml` (D2, D3), and for now a text copy of each array (D10).
2. Arrays are stored as f32. X_eTaL reads them as Float (f64).
   Comparisons use tolerances an f32 computation can meet (D4).
3. Every capture carries the metadata of D3. A capture without it is
   refused, by the adapter's writer and by the X_eTaL reader.
4. Axis order is fixed and written in the metadata. Attention
   patterns are `layer head query key`, row-major, so a query row is
   contiguous.
5. X_eTaL reads arrays only through the extension (D1). It never
   parses binary data itself and never reads the Python environment.

## Capture format

(Runs of experiments use the run format of D14.)

```
runs/<name>/
  capture.toml      metadata, all values arrays of strings (D2)
  attn.xta          f32, layer head query key
  logits.xta        f32, vocab (the last position) or position vocab
  attn.txt, logits.txt  the same arrays as text numbers (D10), until ask X1 lands
```

XTLARR01, as specified in X_eTaL-gpu's `docs/binary-arrays.md`: the
8-byte magic `XTLARR01`, a scalar tag (1 f32, 2 f64, 3 i64), the rank
(0-9), 6 reserved zero bytes, one little-endian u64 per dimension, then
the little-endian payload, row-major. Truncation and extra bytes are
errors.

`capture.toml` (every value an array of strings, so X_eTaL's built-in
`"file" []L_IST "key"` reads it; numbers go through `n_umbers`):

```toml
format         = ["xetal-circuits-capture-1"]
model          = ["gpt2"]
revision       = ["607a30d783dfa663caf39e06633721c8d4cfcd7e"]
library        = ["transformer-lens 4.4.0", "torch 2.15.0", "transformers 5.23.0"]
device         = ["cpu"]
dtype          = ["float32"]
seed           = ["0"]
prompt_kind    = ["repeated-random"]     # or "text"
prompt         = ["<the exact prompt text, or empty for token prompts>"]
token_ids      = ["50256", "4023", ...]
tokens         = ["<|endoftext|>", " foo", ...]
arrays         = ["attn", "logits"]
text_arrays    = ["attn", "logits"]       # written as <name>.txt too (D10)
attn_axes      = ["layer", "head", "query", "key"]
attn_shape     = ["12", "12", "101", "101"]
attn_layers    = ["0", "1", ..., "11"]       # the model layer of each attn row
logits_axes    = ["vocab"]
logits_shape   = ["50257"]
logits_position = ["100"]
```

The shapes in the TOML must equal the shapes in the `.xta` headers.
Both readers check this.

## Decisions register

| #  | Decision | Reason |
| -- | -------- | ------ |
| D1 | X_eTaL reads model tensors through a native extension in X_eTaL-extensions. It is built like the `image` extension: a Rust shared library (ABI V1) behind a typed facade written with `lib/Ffi.xtlm`. Run with `xetal-x`. Its functions: `r_ead : text -> floats` (the whole array, any rank), `a_t : text int -> floats` (one slice along the first axis, such as one layer), `s_hape : text -> ints` (the header only). | User's choice. Keeps binary parsing out of the language core. ABI V1 already passes dense row-major f64 arrays up to rank 9. One-layer slices keep a Qwen3-4B capture (about 830 MB as f64) workable. |
| D2 | Metadata lives in a TOML file next to the arrays, read with the built-ins `[]L_IST` and `[]T_ABLE`. Every value is an array of strings. | User's choice. No extension code is needed for metadata. Any tool can read it, and test fixtures diff in git. `[]L_IST` reads arrays of strings only, so scalars are one-element arrays. |
| D3 | The array file format is XTLARR01, from X_eTaL-gpu, not safetensors. The adapter writes it with a small numpy writer. The extension reuses X_eTaL-gpu's reader (`xetal_gpu_xir::binary`), moved into a crate both repositories share rather than copied. | User's choice. One binary format across the X_eTaL repositories, and GPU sessions bind the same files (`gp:b_indFile`). It is simple enough to write and check in a few lines. Python tools convert from safetensors when needed. |
| D4 | Captures are f32. Checks use f32-sized tolerances: attention rows sum to 1 within 1e-4, and agreement with TransformerLens within 1e-5 relative. | f32 is the GPU's native width (the M1 Max has no f64). TransformerLens runs GPT-2 in f32. X_eTaL-gpu found tighter tolerances unmeetable on f32 hardware. |
| D5 | In-context learning work is split with X_eTaL-ML. X_eTaL-ML keeps the teaching demos: a hand-built ICL circuit on its Attention library, a toy trained in X_eTaL, and browser pages. X_eTaL-circuits does the experiments on real models (GPT-2, Qwen) and the causal tooling, reusing X_eTaL-ML's `Attention`, `Norm` and `NN` libraries rather than redefining them. | User's choice. Avoids two copies of the same study and keeps each repository's character. |
| D7 | The extension reads **both** XTLARR01 and safetensors files, telling them apart by their first bytes (`XTLARR01`, or safetensors' 8-byte header length followed by `{`). For safetensors: list the tensor names, read a tensor by name (whole, or one first-axis slice), and its shape. f32, f64, f16 and bf16 are read as Float. The adapter still writes XTLARR01 captures (D3), and can also write the same arrays as one `capture.safetensors`. This replaces the "not safetensors" part of D3. | User's choice. Captures stay in the format GPU sessions bind, while X_eTaL can open tensors from the wider ML world (model weights, the paper authors' outputs, other tools) without a conversion step. |
| D6 | GPT-2 is loaded with TransformerLens 4.4 (`TransformerBridge.boot_transformers`), without compatibility mode unless a comparison with old `HookedTransformer` results needs it. The revision is pinned. | The default matches Hugging Face's numbers, and so the paper authors' code. The probe in `docs/reference.md` found CPU, MPS and compatibility mode in agreement on the attention-pattern scores. |
| D8 | The shared array-file crate (XTLARR01 and safetensors) belongs to X_eTaL-extensions, as `crates/xetal-arrayfile`. X_eTaL-gpu switches its `binary.rs` to it. | User's choice. X_eTaL-gpu already depends on X_eTaL-extensions (a pinned commit), and not the other way round. |
| D9 | This repository never edits another. What it needs from a sibling is written as an ask in `docs/xetal-<repository>-asks.md` (X_eTaL-extensions, X_eTaL-gpu, X_eTaL-ML, X_eTaL-libraries), which that repository's own plan takes. A step whose work lies elsewhere is reserved for that repository in agentrail and closed when the ask lands. | User's rule. |
| D10 | For now X_eTaL reads captures as text: the adapter writes `<name>.txt` beside each `<name>.xta`, row-major with one line per last-axis row. Each f32 is written as the shortest decimal of its f64 widening, so X_eTaL's `n_umbers []N_GET` gives exactly the values a binary reader will give. X_eTaL reshapes them by `<name>_shape` from capture.toml. The X_eTaL code reads arrays in one place, so it moves to the extension (X1) when that lands. The text files then stop. | User's choice: the X_eTaL steps go ahead without waiting for X1. A GPT-2 Small capture as text is about 30 MB, workable. Qwen-sized captures wait for X1. Values match the binary files exactly (a test with the pinned X_eTaL). |
| D11 | `XETAL_COMMIT` moved to 0166a52a for `[]N_GRID` (QD8). That X_eTaL finds a relative `[]L_IST` path beside the file naming it (QD9), here the Capture library, while `[]N_GET` reads from the working directory. So `Capture` takes a capture directory as an absolute path and refuses a relative one (`error[capture]`); the command-line scripts make the path absolute. | The heatmap needs `[]N_GRID`. One absolute path means both readers see the same file. The pin moves on purpose, with the tests, never silently. |
| D12 | Live pages on GitHub Pages: a static site built by a script from committed captures only, its SVGs drawn by X_eTaL; the page only picks among them (no model, no server, no extension in the browser). Deployed by a GitHub Actions workflow on a push to main. | User's choice. Every picture viewable without a clone. Pictures drawn ahead of time avoid the browser's lack of native extensions. |
| D13 | One evidence key in every picture: each component and edge carries the level it has reached. Dashed: observed (an attention pattern or attribution score only). Solid: tested (an intervention moves the margin, against matched random controls). Thick: confirmed (also on held-out prompts). Attention heatmaps are always labeled observation. | User's choice. The model map becomes a running record of what is discovered where, and how sure it is (research rule 1). |
| D14 | The induction experiment (experiments/induction.toml): the clean prompt is BOS + t distinct random tokens twice; its corrupted twin keeps BOS and the first copy and replaces the second copy with t fresh distinct tokens found nowhere in the clean prompt, so the two line up position by position (checked by `twins.check`). The metric is the logit difference at each second-copy position q = t+1 .. 2t-1 (0-based): logit(clean next token) minus logit(twin's next token at q), and its mean. Results are written as run directories (`run.toml`, format `xetal-circuits-run-1`, every value a list of strings, plus each array as .xta and .txt, shaped by `<name>_shape`). Finding seeds choose heads; held-out seeds only check them, and the file refuses a seed in both. | Rule 3: a margin, not accuracy. A logit difference does not depend on the rest of the vocabulary (the softmax's normalizer cancels), the usual choice for patching. The twin gives induction nothing to copy and keeps every position, so the same positions are compared. On GPT-2 Small (seeds 0-2, 100) the clean mean is 14 to 18 and the twin's -0.3 to 2.5. Only the metric is kept, not every position's logits (about 35 MB of text per run). |
| D15 | Head ablation: a head's output is its slice of `blocks.{l}.attn.hook_z` (before W_O). Zero ablation sets it to 0; mean ablation sets it to its mean over the finding seeds' twins, position by position (the same reference for finding and held-out seeds, recorded in run.toml as `mean_over`). A head's effect is the clean mean logit difference minus the ablated one, so positive means the output needs the head. One run per seed (`seed-N`), both matrices layer x head. | Mean ablation keeps the head's output on the distribution the model saw, so it measures the information the head adds; zero ablation is kept beside it because it is the usual baseline and disagrees in instructive ways (it flags layer-0 heads whose mean output matters as such). Over the finding seeds mean ablation ranks 5.1 (3.5), 4.11 (1.6), 7.6, 8.5, 5.5, 6.9: single heads close only a part of the gap of about 14, as heads back each other up. Not yet compared with controls (D16). |
| D16 | Activation patching copies one activation between the twins. Denoising runs the twin with the activation from the clean prompt: the fraction of the clean-twin gap in mean logit difference it restores. Noising runs the clean prompt with the activation from the twin: the fraction it destroys. Patched: the residual stream entering each layer at each position (`hook_resid_pre`, layer x position), each head's output at every position (`hook_z`, layer x head, both directions), and the six heads that restore the most by denoising, position by position (rank x position, the heads named in run.toml's `leading_heads`). One run per seed. | Denoising asks what suffices to bring the behavior back, noising what is needed for it: they differ when heads back each other up. Fractions of the gap compare across seeds whose baselines differ. Patching the whole input recovers each side exactly (a test). On seed 0 the heads that restore the most are 6.9, 5.1, 7.2, 5.5, 9.6 and 10.1, each 6-13% of the gap; noising ranks 5.1, 7.6, 0.1, 8.5, 5.5, 6.9. |
| D17 | Matched random controls: for each head and seed, 20 changes to the head's output (hook_z) of the same length as the real intervention's change at each position (mean ablation: mean minus clean; denoising: clean minus twin), in uniformly random directions, run as one batch; seeded by seed, layer and head. A head passes a method when its mean effect over the seeds is at least 5% (of the clean logit difference for ablation, of the gap for denoising) and above the seed-averaged effect of every one of its 20 controls (chance about 1 in 21). Controls are run for mean ablation and denoising. | A random change of the same size tells whether the effect comes from what the head carries or only from changing the activation that much. Random heads are not used as the control: they are the candidates themselves. Without the 5% floor 74 heads passed mean ablation and 70 denoising, because the controls average to almost 0 over 10 seeds and even 0.3% beats them; the floor asks for an effect that matters. It was chosen after seeing that, so it is fixed now, before the held-out seeds, which then test it (D13: tested on the finding seeds, confirmed on held-out ones). With it: mean ablation 5.1, 4.11, 7.6, 8.5, 5.5, 6.9; denoising 6.9, 5.1, 7.2, 5.5, 7.10, 9.9, 9.6, 10.1, 0.1. |
| D18 | Held-out validation: ablation, patching and controls are run again on the experiment's held-out seeds (100-109, never used to choose heads or the threshold), with the same rule (D17) and the same mean-ablation reference (the finding seeds' twins, D15). A head is confirmed for a method when it passes on both seed sets, tested when it passes on the finding seeds only (D13); X_eTaL refuses held-out runs sharing a seed with the finding runs. | The rule and the 5% floor were fixed before these runs, so passing again is not tuned to them. Result: mean ablation confirms 5.1 (22% finding, 22% held-out), 4.11 (10%, 13%), 7.6, 8.5, 5.5; 6.9 stays tested (5%, then 4%). Denoising confirms all nine: 6.9, 5.1, 7.2, 5.5, 7.10, 9.9, 9.6, 10.1, 0.1, each within about 1 point of its finding-seed effect. |
| D19 | The graph of paths: a sender is a head `layer.head` or `embed`; a receiver is a head's query, key or value input `layer.head.q|k|v` or `logits`; an edge `"sender receiver"` exists when the receiver is in a later layer (the logits after every layer). Python (`graph`, `edges`) and X_eTaL (`xetal/Edges`, five Ints per edge) parse and refuse the same names. GPT-2 Small has 29,089 edges with all three inputs. An edges experiment (`experiments/*-edges.toml`) names its base experiment beside it, the senders and receivers in scope (`all` or lists), the inputs, which edges to path-patch (`all`, or the top N by edge attribution) and edges always path-patched (the circuit's). MLPs are not senders or receivers yet. | Query, key and value are separate receivers because they are different compositions: an induction head finds its earlier token through its key (K-composition with a previous-token head), while its query and value read other things. Naming edges by text keeps every file readable by both languages. 29,089 edges times 20 controls and 20 seeds is too many to path-patch one by one, hence the attribution ranking first. MLPs wait until their outputs are captured. |
| D20 | Path patching: a sender's difference is what it writes into the residual stream on the clean prompt minus on the twin (a head's z @ W_O, the embeddings' input to layer 0); a receiver reads the twin's residual stream plus that difference, nothing else changes, and everything after the receiver runs as usual. The twin and the metric depend on the receiver's input. Keys: the key twin (BOS, the fresh tokens, then the clean second copy), which differs where keys look; queries, values and the logits: the twin of D14. Queries and keys: the fraction of the receiver head's attention-score gap (before the softmax, mean over the second copy's queries, at the induction target, the token after the earlier occurrence) that the patch restores. Values and the logits: the fraction of the logit-difference gap (D16). The metric's tokens are those of D14 for both twins (the fresh tokens are the same). One run per seed holds the sender x receiver matrix (145 x 433 for GPT-2 Small, 0 where there is no edge). | D14's twin shares the first copy with the clean prompt, so it cannot test keys: previous-token information at the keys is the same in both, and every key edge would read 0 (seen on seed 0). On the key twin the output metric is confounded: a restored key makes the head attend to a fresh token and copy it, the metric's wrong token. Attention probabilities hide partial restoration behind the softmax (4.11 into 5.1's key: 1%); scores, where a sender's contribution enters additively, show it (38%). Checks: q from the residual stream by hand equals the model's (1e-5); patching a head into every reader (all later q, k, v, MLP inputs and the logits) equals patching its output (D16) within 1e-6. On seeds 0 and 1, 4.11 restores 26-46% of every induction head's key gap, ahead of 3.7, 2.2 and 5.6. MLPs are not senders yet, which limits the query side (GPT-2's first MLP carries much of a token's identity). |
| D21 | Edge attribution: an edge's attribution is the sender's difference (D20) dotted with the gradient of the receiver's metric with respect to the receiver's input, on the receiver's twin, over the same gap: the first-order term of path patching. Queries and keys: the receiving head's target attention score reads only its own query and key, so the gradient is taken through that head's LayerNorm1 and W_Q or W_K at the twin's residual stream. Values and the logits: one backward pass of the logit difference on the twin gives the gradient at every head's value (carried back through W_V and LayerNorm1) and at the final LayerNorm's input. Each run holds `edge_attribution` (sender x receiver, fractions like `edge_effect`) and `receiver_gap` (each receiver's gap in its metric's units). Choosing edges to path-patch (`["top", N]` in an edges experiment): edges are ranked by the change they make in their receiver's metric, attribution times gap, the mean over the finding seeds, separately for the score metric (q, k) and the logit metric (v, logits); the N largest of each are taken, then the `always` edges. | Path patching costs one forward pass per receiver (about 10 minutes a seed on a CPU); attribution gives all 29,089 edges in about 2 seconds. Measured on seed 0 against path patching, in the metric's units: Pearson 0.982 over the score edges and 0.999 over the logit edges; the 200 largest path-patched edges of each metric all have attribution's sign and all fall within attribution's 300 largest; the five 4.11 key edges rank 1st, 3rd, 4th, 6th and 10th of the score edges by both. Fractions do not rank across receivers: heads whose induction score barely differs between the twins (3.5, 5.4: gaps near 0) give fractions near 100 for tiny changes, and ranked by fraction the 4.11 key edges fall near 1,400th. The two metrics' units do not compare, hence N of each. |
| D22 | Edge verdicts: the edges chosen by D21 are path-patched (D20) on each seed with 20 matched random controls each: the sender's difference replaced by a vector of the same length at each position in a random direction (seeded by the seed and the edge's name), added to the same receiver on the same twin, in the same units. An edge is judged only when its receiver's gap is positive on every seed. A judged edge passes when the size of its mean effect over the seeds is at least 5% of the receiver's gap and larger than the size of every control's mean: two-sided, unlike D17's heads. The report ranks passing edges by their change in the receiver's metric (attention score or logit difference), each metric apart. Grids show passing edges per input kind, sender x receiver, percents capped at 100 in size; the logits as a layer x head grid. | Two-sided because an edge that pushes its receiver away is composition too (4.7 lowers every induction head's key score by 12-19%; 6.6 the queries of later heads); D17's heads were scored one-sided before held-out seeds and stay so. The judged rule was added after seeing the finding seeds' runs: 4.11's gap at the induction target (not a previous-token head's job) is negative on two seeds, and the mean of percents there reached 656% (one seed 6,893%); 23 edges are not judged. The 5% floor and 20 controls are D17's, fixed before held-out seeds. Finding seeds: 186 of 400 edges pass (176 into queries and keys, 10 into the logits); 4.11 feeds the key of every induction head (17-45%, controls at most 2%). |

## Open

- An interactive explorer in the browser (running X_eTaL there, not
  only showing pictures drawn ahead of time, D12). Native extensions do
  not load in WebAssembly, so it would carry its data with the page, as
  X_eTaL-ML's pages do.
- Until ask X1 lands, X_eTaL reads captures as text (D10).
